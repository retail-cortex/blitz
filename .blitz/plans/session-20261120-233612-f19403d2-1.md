## Step-by-Step Plan

### 1. Fix the `TestEnterprisePolicyCommand` Policy Write Order Race
- **Root cause:** In `pkg/enterprise/policy.go` (`RefreshPolicy`), `layOutPolicy(dir, env)` swaps `dir/policy/rules/style.md` into place *before* `writeFile(dir, PolicyFile, state)` writes `policy.json` (which contains `Explain`). Under instrumented coverage timing, `apps/cli/enterprise_test.go:571` (`TestEnterprisePolicyCommand`) polls `blitz enterprise policy` and sees `rule/style` before `policy.json` is written, causing the `explain` assertions (`connectors.own`, `mcp.own`) to fail and dropping all of `apps/cli:cli_test` shard 4 from coverage.
- **Changes:**
  - `pkg/enterprise/policy.go`: Marshal and atomically write `PolicyFile` (`policy.json`) before swapping `policyDir` in `layOutPolicy` (or prepare `policy.next`, write `policy.json`, then swap `policyDir` and write `policy.etag`), so readers never observe new policy rules ahead of their `policy.json` metadata.
  - `pkg/enterprise/policy_test.go` (or existing enterprise tests): Add a regression test verifying `policy.json` and laid-out rules stay consistent on refresh.
  - `apps/cli/enterprise_test.go`: Confirm `TestEnterprisePolicyCommand` passes reliably under `--config=race` and coverage instrumentation.

## Risks & Mitigations
- **Colima VM memory/disk pressure:** Instrumented Go `-race` builds + Bazel output base can use 10–15 GB disk and 6–8 GB RAM. *Mitigation:* Check Colima VM resources first, use a dedicated Bazel cache volume, and pass `--jobs` / `--local_ram_resources` if needed.
- **macOS bind-mount I/O overhead in Colima:** Building Bazel's output base on a virtiofs/sshfs mount can be slow. *Mitigation:* Keep `--output_user_root` inside the container's native Linux filesystem / Docker volume (`/var/cache/bazel`), mounting only the repo source tree at `/workspace`.
- **Architecture mismatch for gVisor (`runsc`):** Apple Silicon Macs run `linux/arm64` in Colima, whereas CI downloads `x86_64` gVisor. *Mitigation:* Pull the `aarch64` `runsc` release when container arch is `arm64`, or gracefully skip `TestGVisor` if unavailable while ensuring all bubblewrap and PTY tests pass.
- **`apps/tray` untested library:** `apps/tray` is a thin `main` entrypoint; check if it affects the floor (note: `tools/coverage` lists untested packages separately without counting them against the percentage, unless a test links them).
